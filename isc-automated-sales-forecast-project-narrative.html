ISC Automated Sales Forecast

Project narrative — what it does, where it stands, what's next  ·  July 14, 2025

The problem it solves

Every week before a GM meeting, a Sales VP has to manually export their pipeline from IBM Sales Cloud (ISC), copy deal data into a spreadsheet, write a narrative summary, and build a PowerPoint — a process that takes 60–90 minutes and is error-prone because it's done by hand under time pressure.

There's no automated way to see what changed since last week: which deals were promoted, which slipped, which dropped out entirely. That comparison lives only in the VP's memory.

The core value proposition: Replace that 90-minute manual process with a single local web app that loads the live pipeline, scores every deal with watsonx.ai, surfaces week-over-week changes automatically, and generates the GM PowerPoint in one click.

What the app does today

  • ⟳
    Refresh Data
    Loads 206 live opportunities from ISC via a HAR export (IBM w3id passkey auth blocks automated scraping — HAR is the practical workaround). Stores to local SQLite in under 2 seconds.
  • ⬡
    Score with watsonx.ai
    Runs automatically after every refresh. Each deal gets a confidence score (0–100) and tier (High / Medium / Low) using a rules-based engine today, switchable to a live watsonx.ai llama-3-70b model via a single .env flag. Scores are persisted to the database — not just computed in memory.
  • ✍
    Generate Narrative
    watsonx.ai writes a GM meeting narrative paragraph + bullet points scoped to whatever filter Dushyant has applied — e.g. just Q3 Commit deals, or just one geography. Mock mode produces realistic output when live credentials aren't available.
  • ⇄
    What Changed (week-over-week diff)
    Compares the live pipeline against the last saved baseline snapshot. Surfaces promoted deals, demoted deals, slipped close dates, amount changes, new deals, and removals — each in a drill-down modal with the before/after confidence score delta.
  • 📊
    Baseline & Generate GM Report
    One click saves today's pipeline as the new baseline (timestamped, not ISO-week, so two snapshots in the same week don't collide) and immediately generates a formatted PowerPoint for the GM meeting. Next week's diff compares against this exact snapshot.

How Dushyant uses it

The app uses a status-driven action bar — five flat buttons, always available, no numbered sequence lock. Each button shows a timestamp chip after it runs (Done · 7:06 AM in green, or an amber Score failed if something went wrong).

This matters because Dushyant's real workflow isn't linear. He might refresh data three times before a meeting, re-score after updating a deal in Salesforce, and run the diff twice to compare two different filter views. The old numbered-step strip forced a one-way sequence — the new action bar treats every action as independently re-runnable at any time.

Tested today (July 14): Action bar renders correctly, all 5 buttons fire their handlers, status chips update with timestamps after each action, the What Changed diff modal shows before/after confidence scores correctly (e.g. Labcorp: 28 → 42, +14 pts after stage promotion).

The one technical constraint worth knowing

Why HAR export instead of live API sync? IBM Sales Cloud uses Salesforce CRM Analytics protected by IBM w3id SSO with passkey (biometric/device-bound) authentication. Automated login via Playwright or cookie injection was thoroughly attempted across 8 approaches over 5+ hours — passkeys are registered per browser and bound to the OS Secure Enclave, making programmatic auth structurally impossible without IBM IT involvement. The HAR export workaround (browser DevTools → copy network response) takes about 60 seconds and is reliable — it's the practical solution until an official ISC API or service account is available.
