Why This Couldn't Be Done Another Way

The user's core assertion — that iterative AI-assisted development delivered more in 9 days than a traditional spec-then-build approach could — is well-supported by the log:

  • Session 1 alone required 8 distinct authentication architecture attempts before finding the HAR solution. A traditional approach would have stalled here for days waiting for Salesforce OAuth approval.
  • 5 consecutive sessions (32–36) were spent on a single CSS bug (border-collapse: collapse silently killing position: sticky). Each session built on the previous diagnosis. No spec document could have anticipated this.
  • The app's architecture changed 3 times in 9 days: rule-based → watsonx-augmented → multi-user SSO → Pipeline Intelligence Engine. Each pivot happened because the prior version was working and visible, triggering the next insight.
  • 43 sessions = 43 closed feedback loops. A traditional waterfall spec → design → build → test cycle for the same feature set would take 6–8 weeks minimum with a 2-person team.
